[23.07.2026 17:39] CN: "Signal + Matrix + Session + Briar = NurChat" — это маркетинговый слоган, а не архитектура. Каждый из этих протоколов решает разные и частично противоречащие друг другу проблемы:
Signal — централизованный сервер, доверенная инфраструктура, но лучшее в классе E2EE (Double Ratchet)
Matrix — федерация, но это ценой сложности синхронизации состояния между серверами (room state resolution — один из самых больных мест в реализации Matrix)
Session — анонимность без телефона через onion-routing поверх собственной блокчейн-сети (Session/Lokinet), это отдельная сетевая инфраструктура
Briar — P2P через Tor/Bluetooth, специально без сервера вообще, философия прямо противоположна Matrix-федерации
Совместить "P2P без сервера" (Briar) и "федерация серверов" (Matrix) в одном протоколе — это не гибрид лучшего, это два взаимоисключающих способа доставки сообщений одновременно. Один разработчик, у которого признанно нет бюджета на сервера, не выкатит и не будет поддерживать: FastAPI-сервер + Postgres + Redis + Alembic + WebSocket-менеджер + federation protocol + P2P на Rust + TURN/STUN для звонков. Это стек, который тянет команда из 5-8 человек на full-time, не сайд-проект.
