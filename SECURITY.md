# Политика безопасности

## Поддерживаемые версии

Мы выпускаем исправления только для последней версии — проект молодой,
срок жизни релизов короткий. Обновляйтесь.

| Версия | Поддержка |
|--------|-----------|
| latest release | ✅ |
| старее | ❌ обновитесь |

## Как сообщить об уязвимости

**Не создавайте публичный issue для уязвимостей.**

Используйте [Private vulnerability report](https://github.com/NurApps/NurChat/security/advisories/new)
на GitHub — или напишите на почту из профиля организации, если GitHub
недоступен.

### Что приложить

- Описание проблемы и условий воспроизведения
- Версию приложения/сервера (Настройки → О программе, или git hash)
- PoC, если есть (мы не публикуем его без вашего согласия)

### Наши обязательства

- **Ответ в течение 72 часов** — подтвердим получение
- **Оценка в течение 7 дней** — подтвердим или оспорим, назовём срок фикса
- Критичные уязвимости чинятся в приоритетном порядке; после выпуска
  патча мы опубликуем advisory с указанием автора находки
- Публичное раскрытие согласуется с вами (по умолчанию — 90 дней)

### Чего мы просим

- Не эксплуатировать найденное на чужих данных и живых серверах
- Дать разумное время на фикс до публичного поста
- Не тестировать DoS-ом публичный релей

## Scope: что считается уязвимостью

В порядке приоритета:

1. **Криптография**: обход Double Ratchet, replay, подмена identity ключей,
   downgrade X3DH (например, навязывание fallback без OPK там, где OPK есть)
2. **Компрометация клиента**: XSS до кражи ключей, инъекции в рендер
   сообщений/медиа
3. **Сервер**: эскалация привилегий, доступ к чужим чатам/файлам,
   обход аутентификации, SQLi, SSRF
4. **Транспорт**: downgrade шифрования, спуфинг WS/signaling

Не является уязвимостью (известные ограничения, задокументированы в README):

- Релей видит метаданные (кто, кому, когда)
- Приватные ключи извлекаются при компрометации устройства
- Отсутствие внешнего аудита
