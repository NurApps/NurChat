# Хост-режим: свой relay из приложения

> Коротко: приложение поднимает локальный relay (он и так стартует при запуске),
> скачивает проверенный `cloudflared` и открывает к нему временный публичный
> адрес. Друзья подключаются по этому адресу, регистрация закрыта инвайт-кодом.
> Переписка остаётся E2E-зашифрованной — relay, как и раньше, «глухой».

## Что делает хост-режим

1. Проверяет, что локальный relay отвечает на `127.0.0.1:8000`.
2. Ищет `cloudflared`: `NURCHAT_CLOUDFLARED` → путь, сохранённый в UI →
   PATH → скачивание закреплённой версии (`2026.10.3`) со сверкой SHA-256
   (несовпадение отклоняется). Бинарь кладётся в
   `%APPDATA%/…/cloudflared/<версия>/`. Автоскачивание есть только для
   Windows и Linux amd64; на macOS/ARM путь задаётся вручную.
3. Запускает `cloudflared tunnel --url http://127.0.0.1:8000 --no-autoupdate`,
   читает адрес `https://*.trycloudflare.com` из stderr.
4. Проверяет адрес снаружи: `GET <url>/health` должен вернуть
   `"service": "NurChat Server"` — иначе туннель считается нерабочим.
5. Закрывает регистрацию (`REGISTRATION_MODE=invite`) и показывает код.
6. Следит за процессом: при падении перезапускает (до 3 раз), статус летит
   в UI (`host-status`). При выходе из приложения туннель гасится.

Автозапуск и ручной путь к `cloudflared` запоминаются в `host.json` в каталоге
приложения; автозапуск срабатывает после готовности локального relay.

## Ограничения MVP (честно)

- **Адрес временный.** Quick Tunnel выдаёт новый поддомен при каждом старте.
  Это плата за нулевую настройку: нет аккаунта Cloudflare, DNS и токенов.
- **Quick Tunnel — тестовый режим Cloudflare.** Возможны лимиты и обрывы.
  Idle-таймаут прокси ~100с, поэтому сервер шлёт WS-ping каждые 25с.
- **Лимиты считаются по IP.** Relay доверяет `X-Forwarded-For` только от
  loopback-туннеля, поэтому видит реальные адреса (а не 127.0.0.1 у всех).
  Друзья за одним NAT делят лимит — при большом числе возможны ложные
  срабатывания.
- **Нет входящих портов.** Нужен только исходящий HTTPS; NAT/firewall
  настраивать не надо.
- **Звонки** идут напрямую (WebRTC), но за симметричным NAT без TURN могут
  не соединиться — см. `TURN_*` в `.env.example`.

## Как включить

1. Запустите приложение (локальный relay поднимается сам).
2. Настройки → «О приложении» → блок **Хост-режим: мой relay**.
3. «Запустить хост-режим», дождитесь статуса «работает».
   Если cloudflared не скачался (macOS/ARM, блокировка загрузки), откройте
   «cloudflared не найден? Указать вручную», скачайте бинарь по ссылке и
   вставьте полный путь к файлу — затем запустите режим снова.
4. Скопируйте приглашение: адрес `https://…trycloudflare.com` + код.
5. Друг: экран подключения → «Чужой relay» → вставляет адрес. При регистрации
   вводит код приглашения.

Регистрацию можно снова открыть кнопкой «Открыть» — тогда аккаунт сможет
создать любой, кто знает адрес.

## Безопасность

- Приватные ключи и расшифровка — только на устройствах; relay принимает
  `encrypted_content` и не видит текст.
- Инвайт-код сравнивается constant-time; пустой ожидаемый код = регистрация
  закрыта (fail-closed).
- `/api/host/config`, `/api/host/invite`, `/api/host/open` доступны только с
  loopback **и** только без `X-Forwarded-For`/`X-Real-IP`: запросы через
  туннель приходят с `127.0.0.1`, но Cloudflare всегда добавляет эти заголовки.
- `/health` отдаёт `relay_id` — усечённый хеш ключа relay. Он нужен, чтобы
  отличить «тот самый» relay; при эфемерных ключах меняется вместе с ними.
- `*.trycloudflare.com` разрешён в проверке `Host` только при наличии
  `CF-Ray`/`CF-Connecting-IP` (их ставит edge Cloudflare). Прямой запрос с
  поддельным Host по-прежнему получает 400; DNS-rebinding не ослаблен.

## Постоянный адрес (апгрейд)

Quick Tunnel — для «попробовать». Для постоянного адреса:

1. `cloudflared tunnel login`
2. `cloudflared tunnel create nurchat`
3. `cloudflared tunnel route dns nurchat relay.example.com`
4. Запуск: `cloudflared tunnel run --url http://127.0.0.1:8000 nurchat`
   (или конфиг `~/.cloudflared/config.yml`).
5. В `.env` relay:
   ```
   CORS_ORIGINS=https://relay.example.com,tauri://localhost,http://tauri.localhost,https://tauri.localhost
   ```
   и у клиентов `VITE_API_HOST=relay.example.com`, `VITE_API_PROTOCOL=https`.

Альтернатива без Cloudflare-аккаунта — Tailscale Funnel или любой reverse-proxy
на VPS. Правило одно: снаружи только HTTPS, relay слушает loopback.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `REGISTRATION_MODE` | `open` или `invite` |
| `REGISTRATION_INVITE_CODE` | Код; пустой при `invite` = регистрация закрыта |
| `NURCHAT_CLOUDFLARED` | Путь к своему бинарю cloudflared; приоритет выше пути из UI, PATH и автозагрузки |

Политика хранится в `.env` рядом с рабочим каталогом сервера (обновляется
кнопками в UI).

## Диагностика

| Симптом | Причина / что делать |
|---|---|
| «SHA-256 не совпал» | Обрыв/подмена загрузки. Повторите; при повторе — проверьте прокси/антивирус. |
| «Туннель не поднялся за 45 секунд» | Нет исходящего HTTPS, блокировка cloudflared firewall/антивирусом. |
| «Туннель создан, но снаружи /health не отвечает» | Локальный relay не слушает :8000 или отдаёт чужой сервис. |
| Адрес перестал работать | Quick Tunnel перезапустился — скопируйте новый адрес. |
| Регистрация просит код, а его нет | Настройки → Хост-режим: код показан под адресом. |

Логи: `[cloudflared]` в логе приложения (dev — консоль, prod — файл лога Tauri).
